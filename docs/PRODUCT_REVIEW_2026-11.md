# Product review, November 2026: the plan to be the first choice

Written 2026-11-05 against commit `712cd14` (3.17.0 plus the unreleased GitLab and Codex readers). The question: what would make Rhythmguard the first choice for any frontend developer or AI-assisted designer working with design systems or frontend code that has scales applied, and what does the product and its code look like today against that bar.

This page is the review and the plan. The evidence is in [`reviews/2026-11-05-findings.md`](./reviews/2026-11-05-findings.md): 160 findings, each checked twice, with a JSON twin that carries every probe, file line and verifier reason. It amends the plan of record, [`COUNCIL_2027-2028.md`](./COUNCIL_2027-2028.md), where the two disagree; section 9 lists each change and the reason.

## Method

Sixty-two agent runs on 2026-11-05, in three stages, every number re-derived from the repository, npm or GitHub on that day.

1. Nine readers mapped the subsystems and the outside world: rules and core, scale and token sources, audit and CLI, the ESLint and Tailwind path, engineering quality, docs and onboarding, the strategy record, the competitor landscape (web research with URLs), and ecosystem signals (download ranges, version shares, upstream release notes).
2. Fourteen reviewers, one per dimension, looked for gaps against the goal by reading the maps and then probing the code: five scratch projects run through the quickstart, CSS and SCSS probes through Stylelint's API, token fixtures in nine formats, class-string probes through ESLint and Oxlint, a 300-stylesheet CI fixture, Stylelint 18 installed into a copy of the repo. They produced 163 findings. Each batch then went to two independent verifiers: one re-ran every cited probe and grepped the code for the capability the finding called missing (114 confirmed, 46 adjusted with a correction, 3 refuted or dropped as duplicates); one rated how much fixing it would move one of the three personas.
3. A cluster pass grouped the 160 survivors into 45 themes. Five planners drafted plans from different angles (AI-assisted authors first, design-system teams first, solo developers first, distribution first, trust and engineering first). Three judges, each playing a different buyer, scored every plan on persona pull, evidence, feasibility for one maintainer, sequencing and clarity. The trust-and-engineering plan won with all three judges (186 points to 174, 173, 160 and 160); the winner absorbed the grafts the judges named, and a completeness critic checked the result for missing items, wrong numbers, contradictions and overreach. The critic's corrections are applied in this text.

The three personas the review measured against:

- **Solo developer.** On a product team, Tailwind or CSS. Wants zero config, an autofix they can trust, feedback in the editor, no noise.
- **Design-system team.** A design engineer whose scale lives in a token package (DTCG, Style Dictionary, Figma), apps in a monorepo. Wants a CI gate, reports, findings that stay stable, no visual regressions. The council's beachhead and the only persona with a buyer.
- **AI-assisted author.** A designer or developer building with Claude Code, Cursor, Copilot, v0, Lovable or Figma Make. The agent writes the CSS or the Tailwind. Wants the scale enforced on generated code, rules the agent can read, and fix loops that converge.

## 1. Summary

Rhythmguard already does the one thing no substitute does: it reads the spacing scale from a DTCG, Style Dictionary, `@theme` or Sass source, names the two nearest steps, and holds CSS, SCSS and Tailwind class strings to a restricted scale, with provenance that says where the scale came from. The core is sound: idempotent, comment-preserving fixes; a content-keyed baseline; 667 tests in 15 seconds, 664 of which pass on Stylelint 18.0.0 without a source change; a 57-repository benchmark gated in CI; attested, tokenless publishing.

It loses users before any rule runs, on failures the review verified by doing them. npm refuses the install next to Stylelint 18, which shipped two days ago. The quickstart's own next command fails on four of five stacks. Five surfaces resolve the scale on their own, so the editor and CI disagree on 40px within ten minutes. `doctor` passes a setup Stylelint cannot load. The CI gate fails the exact fix the finding recommends and passes on zero files. `eslint --fix` rewrites enum members and `aria-label` strings. Every snap moves layout, and no surface says so. The agent pack's first command throws in an ESLint-only Tailwind project. A token file whose values are aliases or unitless numbers parses, counts its tokens, and audits against a guessed scale with an empty warnings list.

None of these is large. All of them are reasons a design-system lead, a solo developer or an agent loop stops trusting the tool, and trust is the only currency this product is paid in.

The plan, in one line: **fix what lies, in order; ship 4.0 as a tested contract; then add hosts, token sets, hooks and review artifacts onto a core that cannot lie.** Five phases from 2026-11-05 to 2027-07-30. The first release, 3.18.0, carries only the Stylelint 18 peer range and ships this week. The last, 4.4.0, is gated on numbers written down now.

What "first choice" honestly means by 2027-07-31: the one tool a design engineer can mandate and an agent loop can converge on. It installs on Stylelint 16.7 to 18, ESLint and Oxlint; reads DTCG, Style Dictionary, Tokens Studio, `@theme` and Sass across files and says when it could not; holds CSS and class strings to one restricted scale with keyed findings, labelled fixes and four exit codes. First by trust in restricted-scale enforcement, measured as 5 external organisations, 3 outside issues and 900 aged weekly downloads with the single largest pinned version removed (1,500 is the stretch figure; no comparable supports it). Not first by downloads: oxlint-tailwindcss reached 1.19M monthly downloads in eight months and @shadcn/lint 8.4M in two, on channels this project does not have.

## 3. The offering today, per persona

**For the design-system team.** The only linter that reads the scale from a DTCG, Style Dictionary, `@theme` or Sass source with provenance and holds CSS and SCSS to it; a content-keyed baseline so moved code is not new drift; `--staged` and `--since` in 0.2 s; `--plan` collapsing drift into adopt, allow and snap decisions; a token contract that checks `var()` chains and ladders, which no token tool does. Against that: a role-named DTCG group (`gap`, `inset`, `stack`), a semantic file aliasing a primitives file, a Tokens Studio export or a `calc(var(--unit) * N)` ladder all fall back to a guessed scale with `warnings: []` (tf-01, tf-02, tf-03, tf-05, tf-08). From a monorepo root every package is judged by `rhythmic-4` because discovery anchors on `process.cwd()` at 13 call sites (cq-12, ds-01). The gate fails the fix the finding recommends because `prefer-token` counts the on-scale literal as new drift (dx-08). Zero files scanned reports 100% clean and passes `--min-cleanliness 100` (dx-09). There is no SARIF (ci-05), no way for a published shared config to name its token package portably (ds-05), and findings are keyed on message text that changed in eight 3.x releases (ds-04).

**For the solo developer.** A 0.63 s `npx rhythmguard` start that found the right scale on four of five scratch stacks, nearest-step messages, idempotent fixes on three surfaces, a plugin that adds 12 ms to a Stylelint process and lints warm in 0.4 ms. Against that: npm refuses the install next to Stylelint 18 (dr-01); the quickstart pastes a config that needs `stylelint-config-tailwindcss`, `postcss-scss` or a parser it never names, so the printed command fails on four of five stacks (dx-01, dx-04, dx-05); the ESLint rule's default scale flags `p-5` on a stock Tailwind project and folds everything above 32px into `p-8` (cs-01); `eslint --fix` visits every string literal, so it rewrites type unions, enum members, `aria-label`, `title` and `data-*` values (cs-04, fix-09); every fix is a snap that moves layout, with no suggestion path and no label (cs-06, fix-01).

**For the AI-assisted author.** Deterministic JSON that is byte-identical across runs, packs for Claude Code, Cursor and Copilot generated from one source block with a drift test, a skill `npx skills add` can install today, and an eval harness with a 12-task hard suite. Against that: the pack tells the agent to run `npx rhythmguard audit . --format json`, which audits against the built-in `[0..32]` instead of the project's scale (ai-01) and throws in any project that installed `eslint-plugin-rhythmguard` without Stylelint, which is every ESLint-only Tailwind app (dx-03, ai-02); each literal is reported twice (ci-01); an invented `var(--space-7)` is listed under `missingTokens` but is never a finding, a lint error or a gate failure (ai-03); the audit rejects file arguments, so nothing checks the file the agent just wrote (ai-05, ci-10); the skill is not indexed by skills.sh search and there is no marketplace manifest (dc-01); and the one eval edition returned a null result on tasks too easy to separate the arms (ai-08).

**On the front page.** The README never mentions DTCG, Style Dictionary, Figma or a token package, although the first run reads them (pos-01). Nearest-step messages, the README's stated difference, are no longer unique: oxlint-tailwindcss prints "Closest in your theme" with pixel values; the real wedge, a scale read from the token file that rejects a value even when Tailwind can express it, is unstated (pos-03). `COMPARISON.md` compares complements and omits every substitute the personas already run, including Stylelint 18's new core rule (pos-04, pos-05).

## 4. Tech and code quality

Strong core, weak edges.

**Strong.** `src/core/value-nodes.js` is the single place value semantics live: one-pass walkers over `postcss-value-parser`, math-bound collection, Sass operand detection and a comment-preserving writer shared by all four rules and the codemod. Option validation is schema-driven and rejects literals in lists, empty scales and unknown presets. Eight contract test files keep the layer graph acyclic, CJS and ESM exports identical, companion versions in lockstep, rule docs present, the playground bundle fresh and at parity with real Stylelint, and the Oxlint plugin loading. Publishing is tokenless with SLSA provenance on all three packages, followed by pack-smoke and registry-smoke installs into clean projects. Sixty-four issue numbers are cited inline next to the behaviour they fixed. Editor latency is measured: 0.37 to 0.53 ms warm with `scale: "auto"`. Renderer output is injection-safe. The code is already Stylelint 18 clean: no `context.fix` anywhere, every fix through `utils.report` callbacks.

**Weak.** Forty-four bare `catch {}` blocks (one inside a string), eight of which swallow user input: a malformed `.rhythmguardrc.json` silently loses its adopt decisions, a throwing `tailwind.config.js` becomes "no known token" (cq-05). Five surfaces resolve their own scale: the audit's `[0..32]`, the recommended config's `[0..64]`, the Stylelint rule's per-file inference that falls back to `rhythmic-4`, the ESLint rule's hand-typed array, and the quickstart's inferred ladder; three of them give different verdicts on 40px (dx-02, dx-06). The audit recovers findings by four regexes over Stylelint message text, 5 of 15 message shapes fall through as off-scale with `value: null`, and no test asserts the regex set covers every message a rule can emit (cq-02). Three rule bodies are 50 to 75% copies, so 17 of 19 rule commits touched two or more files and the Sass operand guard reached two rules of four (cq-01, fix-07). The runtime source has no `@ts-check` and no JSDoc parameters; the hand-written `types/*.d.ts` (735 lines) is checked only against consumer fixtures, and a strict typecheck over `src` reports 148 errors in 25 files (cq-07). One exit code covers a crash, a usage error and a failed gate (ci-02). The audit keeps every AST until the last file and writes 114 MB of JSON and 161 MB of HTML on a 2,001-file corpus at 1.1 GB peak RSS (cq-03), and `--format github` throws above about 100,000 findings because it spreads the array (cq-04). A child-process Tailwind config loader is never called by any test and is dead on Node 22 (cq-06). `doctor` keeps module-level state and calls `process.exit` (cq-11). Twenty-two action pins are mutable tags executing on the maintainer's own hardware (dr-08).

**Delivery.** CI serialises ten jobs onto one Mac mini: 33 to 71 minutes per run, 7 of the last 15 cancelled, while ten GitHub-hosted jobs passed in this repository last week, including a fork pull request verified in 47 seconds (dr-02). Releases are hand-edited in three manifests plus the changelog with no tooling (dr-04). There is one admin, one npm maintainer and no runbook for a month away (dr-03). `SECURITY.md` does not say that the package makes no network calls and executes a project's `tailwind.config.js` (dr-07, ds-11). Node 20 is end of life and still in `engines` and two workflows (dr-05).

## 5. Strongest assets

The plan builds on these and must not re-do them.

1. Token-file-native scale inference with provenance on first contact: DTCG 2025.10 object dimensions, same-file aliases and `$ref` pointers, every Style Dictionary output format, `@theme` in both its restriction and ladder idioms, Sass maps and scalars, 16 installed packages, 21 vendored DTCG conformance cases. Terrazzo validates token-file format only and Style Dictionary validates nothing.
2. The only scale-restricting answer in the Tailwind lane: with a declared scale `p-[13px]` is rejected and fixed to `p-3`, while @shadcn/lint answers `p-3.25` ("same value, on the scale") and oxlint-tailwindcss offers theme steps; the same rule runs unchanged on Oxlint 1.91.0.
3. Idempotent, comment-preserving, span-exact fixes on three surfaces; Sass arithmetic evaluated, reported with "Evaluates to Npx" and never rewritten; token fixes refuse to guess on the index path.
4. A content-keyed baseline and ratchet with `--staged` and `--since`, provenance in every renderer, and `--plan` turning drift into recorded decisions.
5. Evidence discipline: the 57-repo quiet benchmark on every change, a rerunnable competitor bench that corrected the project's own earlier claim, maintainer-confirmed scales from Primer, PatternFly, NHS.UK, Mozilla, WordPress and Mantine, one upstream fix merged.
6. A framework-free core behind an acyclic layer graph, so every host (Stylelint, ESLint, Oxlint, the audit, the playground) is a wrapper.
7. Tokenless, attested publishing with post-publish smoke installs of every package into a clean project; the code already passes on Stylelint 18.
8. Agent packs built from one source with a drift test, a skill the skills CLI can install, and a real, cheap eval harness with resume and refusal handling.

## 6. Biggest gaps

1. The install is refused on Stylelint 18, and the first-run commands fail on four of five stacks (dr-01, dx-01 to dx-05).
2. Five surfaces resolve five scales, and the ESLint rule cannot read `@theme`, a token file or the rc (dx-02, dx-06, cs-03, cs-05).
3. Silent fallbacks: 44 bare catches, token sources with tokens but no lengths, zero files scored 100%, a missing token source exiting 0, a `doctor` that passes a broken setup (cq-05, tf-02, dx-09, ci-02, dx-07).
4. Findings are prose: two per literal, regex classification, baselines keyed on changing text, the gate rejecting the recommended fix (ci-01, cq-02, ds-04, dx-08).
5. Fixes move layout without a word, and `eslint --fix` rewrites any string (fix-01, cs-06, cs-04).
6. Token sets: role-named DTCG, cross-file aliases, Tokens Studio, `calc()` ladders and monorepos all fall back (tf-01, tf-03, tf-08, tf-05, ds-01).
7. Agents cannot find the skill where their tools search, nothing checks the file just written, and the pack's first command throws without Stylelint (dc-01, ai-05, dx-03).
8. Delivery depends on one machine and one person, and the plan of record reads its checkpoints through one lockfile (dr-02, dr-03, eb-11).

## 7. The plan

### Promise

Nobody chose 13px. Rhythmguard reads the spacing scale from your token file and holds CSS, Tailwind classes and your coding agent to it.

### Thesis

The differentiator exists and is under-sold; the losses happen before it is reached. So the order is: make the install work and the first command true (3.18, 3.19); make every surface use one scale, make every fallback loud, and make the ESLint rule trustworthy (3.20, 3.21); read the token set the designer owns in the shape it is stored (3.22); ship one major that turns "findings never change within a major" into a tested fact (4.0); then put the same findings where CI reviews and agents work (4.1 to 4.4). Each step is S or M except the token set, the finding contract, the labelled fixes and the config resolver, which are the four L items the window is sized for.
